# TransDev mobile host (React Native)

This app is the *server* half of TransDev: it starts an HTTP server on the phone's LAN interface, shows the pairing
PIN/QR, tracks connected computers and exposes the shared folders.

```
App.tsx                     three tabs + server lifecycle
src/screens/ServerScreen    status, PIN, QR, sessions, storage, how-to
src/screens/FilesScreen     browse the shared folders from the phone
src/screens/SettingsScreen  device name, PIN rotation, access summary
src/server/httpServer.ts    HTTP/1.1 over react-native-tcp-socket
src/server/localHost.ts     routes: pairing, listing, assets, uploads, storage
src/server/pairing.ts       PIN / QR / sessions / brute-force throttle
```

## Setup

Native projects are generated by the React Native template, so create one and copy this source over it:

```bash
# 1. create a bare project with the same RN version
npx @react-native-community/cli init TransDevMobile --version 0.79.2
cd TransDevMobile

# 2. copy the app source
cp -R /path/to/trans-dev/apps/mobile/{App.tsx,index.js,app.json,src} .

# 3. install the native modules used here
npm install react-native-tcp-socket react-native-fs react-native-network-info \
            react-native-qrcode-svg react-native-svg buffer

# 4. iOS pods + run
cd ios && pod install && cd ..
npm run ios      # or: npm run android
```

Then press **Connect · start server** on the Server tab.

## Platform permissions

**iOS** — `Info.plist`:

```xml
<key>NSLocalNetworkUsageDescription</key>
<string>TransDev runs a local web server so your computer can download files over Wi-Fi.</string>
<key>NSBonjourServices</key>
<array><string>_transdev._tcp</string></array>
```

iOS 14+ prompts for local network access on first bind; if the user declines, the server still starts but is
unreachable from other devices.

**Android** — `AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
```

Plain HTTP to a LAN address is allowed by the default network security config on modern targets; if you have enabled
`cleartextTrafficPermitted="false"` globally, add a `domain-config` exception for the local subnet.

## What already works

- Start/stop the LAN server on port 8787 with a single tap; the address is read from Wi-Fi.
- PIN and QR pairing, session list with per-device revoke, PIN rotation, 5-attempt lockout.
- Browse the shared folders on the phone, see sizes and free space.
- The same HTTP API the dashboard expects: listing, signed asset grants, 4 MB chunked resumable uploads, storage.
- Streams downloads in 256 KB blocks with `Range` support.

## Known limitations (on purpose, for now)

- **Foreground only.** iOS suspends a backgrounded app; the server stops being reachable. A background task plus a
  "keep screen awake" hint is the next step.
- **Documents folder only.** Photos/Documents/Downloads map to `RNFS.DocumentDirectoryPath`. A camera-roll bridge
  (`@react-native-camera-roll/camera-roll`) and system file picker are planned.
- **No TLS.** Same trust model as the Node host: LAN-only, token-authenticated, no encryption against network
  observers.
- **One request at a time per socket** and no `Transfer-Encoding: chunked` — the dashboard sends `Content-Length`,
  and the per-request cap is 32 MB (a 4 MB chunk plus headroom).
- Sessions are in memory, so force-quitting the app revokes every paired computer (a safe default).

## Manual smoke test

1. Start the server; note the URL and PIN.
2. On a computer on the same Wi-Fi, open `http://<ip>:8787`.
3. Pair with the PIN → the Files tab should list `Inbox`, `Photos`, `Documents`, `Downloads`.
4. Upload a file from the browser → it appears in `Inbox`, and the phone's Files tab after a pull-to-refresh.
5. Download it back and compare checksums.
6. On the phone, tap **Remove** next to the browser → the dashboard's next request returns `401`.
